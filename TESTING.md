# Тестовая среда — одна и только одна

Чтобы версии больше не «слоились», у проекта **одна** тестовая сборка и **один** способ её
запускать. Всё остальное (запуск из `build/`, старые распакованные папки, ручные сборки) —
источник путаницы и багов вроде `Usage: poh_cli desktop-session-supervise ...`.

## Канонический способ собрать
```powershell
# из чистого, закоммиченного master:
pwsh scripts/build-portable.ps1
```
На выходе в корне один архив с **хешем коммита в имени**:
`ProxyOpenHub-portable-<дата>-<commit>-win-x64.zip`.
Скрипт всегда собирает **release** GUI + `poh_cli`, кладёт совпадающий `poh_cli.exe` рядом с
GUI и предупреждает, если рабочее дерево грязное (сборка ≠ коммиту).

## Канонический способ запускать (тестерам)
1. Взять **именно этот** zip (имя содержит коммит).
2. **Распаковать в ЧИСТУЮ пустую папку** (не поверх старой).
3. Запустить `proxy_open_hub.exe` **из этой распакованной папки**.
4. Старые распакованные копии — **удалить**, чтобы не запустить случайно.

## Почему так строго (суть бага «разные версии»)
GUI ищет бэкенд `poh_cli.exe` **рядом с собой** (и в родительских папках/`target`). Если рядом
лежит **устаревший** `poh_cli.exe`, новый GUI вызывает старый бэкенд → ошибки и другое
поведение. Именно это давало `Usage: ... <state-path> <profile-id>` без `--gui-pid`: GUI был
новый, а `poh_cli` рядом — старый.

**Правила, которые это исключают:**
- Не запускать `proxy_open_hub.exe` из `apps/desktop_flutter/build/...` для «настоящего» теста —
  только из распакованного канонического zip.
- Не копировать `poh_cli.exe`/`proxy_open_hub.exe` по отдельности между папками.
- В баг-репорте указывать **commit из имени zip** — тестируем ровно ту же сборку.

## Сброс зависшей сессии (если осталась от прошлого запуска)
Из распакованной папки:
```powershell
.\poh_cli.exe desktop-session-reset
```

## Запланированная защита (follow-up для воркера Claude)
Добавить «рукопожатие версий»: GUI при старте проверяет `poh_cli --version` совпадает с
ожидаемым и **громко падает с понятной ошибкой** при несовпадении — вместо тихого вызова
чужого бинаря. Это окончательно убьёт класс багов «разные версии».
